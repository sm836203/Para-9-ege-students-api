# API для учета учеников ЕГЭ

Учебный проект по паре 9: REST API для учёта учеников, которые готовятся к ЕГЭ по истории и обществознанию. Применён подход **API First**: сначала создан контракт OpenAPI 3.0.3, затем по нему сгенерирован каркас Python-сервиса.

**Зачем нужен API:** чтобы репетитор мог вести список учеников, отслеживать текущие и целевые баллы и обновлять данные о подготовке из разных приложений.

## Эндпоинты

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/students` | Получить список учеников; необязательный фильтр `subject` |
| `GET` | `/api/students/{studentId}` | Получить карточку ученика |
| `POST` | `/api/students` | Создать карточку ученика |
| `PATCH` | `/api/students/{studentId}` | Изменить отдельные поля карточки |
| `DELETE` | `/api/students/{studentId}` | Удалить карточку |

В каждой операции предусмотрены `summary`, параметры или тело запроса, успешный ответ `200` и минимум один ошибочный ответ (`400` или `404`) с объяснением. Для учебного задания при создании и удалении используется `200`; в реальных API также распространены `201` и `204`.

DTO описаны в `api.yaml` через `components/schemas`: `StudentCreate`, `StudentUpdate`, `StudentResponse`, `DeleteResult`, `ErrorResponse`, `Subject`, `PreparationStatus`. Во внешнем ответе нет внутренних сущностей и служебных данных. Примеры имён вымышленные.

## Структура проекта

- `api.yaml` — исходная спецификация OpenAPI 3.0.3.
- `service-generated/` — **официально сгенерированный** каркас Python Flask-сервиса (OpenAPI Generator 7.27.0).
- `README.md` — описание проекта и процесса выполнения работы.

При наличии папки `service/` она относится к первоначальному вспомогательному прототипу и **не является** официальным результатом кодогенерации. Для сдачи достаточно `api.yaml`, `service-generated/` и этого README.

## Как выполнялась работа

1. **Способ:** с помощью ИИ-ассистента ChatGPT, модель **GPT-6**, с проверкой человеком.
2. **Итоговые запросы к ассистенту:** передано задание на OpenAPI 3.0 с пятью операциями (GET-список, GET-один, POST, PATCH, DELETE), DTO и ошибочными ответами; затем уточнена тема: «давай лучше REST API для учета учеников, которые готовятся к ЕГЭ по истории и обществознанию.».
3. **Проектирование:** выбраны поля карточки ученика (ФИО, предмет, год ЕГЭ, текущий и целевой баллы, статус), разделены DTO создания, изменения и ответа; предусмотрены диапазоны баллов 0–100, коды `400` и `404`.
4. **Ручная проверка:** файл `api.yaml` открыт в Swagger Editor (<https://editor.swagger.io/>); проверено отображение пяти операций и DTO без ошибок редактора. Синтаксис и ссылки `$ref` также предварительно проверялись локальным скриптом.
5. **Официальная кодогенерация:** на Windows установлен OpenAPI Generator CLI и выполнена команда из корня проекта:

   ```powershell
   openapi-generator-cli.cmd generate -i api.yaml -g python-flask -o service-generated
   ```

   Генератор **7.27.0** создал папку `service-generated/`, включая `openapi_server/controllers/students_controller.py`, модели DTO, `requirements.txt`, `setup.py` и собственный README. Это подтверждено выводом генератора и проверкой созданных файлов.
6. **Ручные исправления после генерации:** сгенерированный код не редактировался. Обновлено описание процесса в корневом README, чтобы отделить первоначальный учебный прототип от официального результата.

## Воспроизведение

Для повторной генерации нужны Java, Node.js/npm и OpenAPI Generator CLI. Из каталога, где находится `api.yaml`, выполнить:

```powershell
npm.cmd install -g @openapitools/openapi-generator-cli
openapi-generator-cli.cmd generate -i api.yaml -g python-flask -o service-generated
```
